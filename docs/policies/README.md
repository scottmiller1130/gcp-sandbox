# Policies

The written policies behind the controls in [docs/security.md](../security.md), mapped to the SOC 2 Trust
Services Criteria in [docs/soc2-controls.md](../soc2-controls.md). Each says what we do and where the
evidence is. **Owner of all policies:** @scottmiller1130. **Review:** at least yearly, and after any
SEV1 incident. A change to a policy is a pull request like any other.

| Policy | Covers |
|---|---|
| [Information security](information-security.md) | Scope, roles, data, encryption |
| [Access control](access-control.md) | Who gets what, approval, quarterly review, removal |
| [Change management](change-management.md) | PRs, reviews, approvals, emergencies, the ledger |
| [Incident response](incident-response.md) | Detect, respond, communicate, learn |
| [Backup and recovery](backup-recovery.md) | Backups, restore drills, RPO/RTO |
| [Vendor management](vendor-management.md) | Third parties and what they can see |
| [Risk assessment](risk-assessment.md) | The risk register and accepted risks |
